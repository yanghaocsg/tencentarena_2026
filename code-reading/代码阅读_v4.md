## 1. 本篇定位与阅读路线

### 1.1 v4 是什么

v4 是「峡谷追猎」PPO 训练工程在 v1 → v2 → v4 → v5 迭代链上的**第三个正式版本**。它的设计动机来自 v4 文档《PPO_v4_设计与优化路线.md》对真实瓶颈的修正：

1. **~340 步死亡的真实原因 = 第二只怪 300 步出现后的双怪包夹**，而不是"穿梭从不使用"。v1/v2/v3 的智能体活不到 500 步怪物加速，双怪从不同方向压缩走位，一次穿梭只能躲一个方向，随后 100 步 CD 内被两只包死。
2. **穿梭的问题不是"用不用"，而是"时机和落点"**：CD 一好就用（约 100、200 步用掉），没把技能留到 300 步双怪包夹的危急窗口；落点可能是死角/障碍，或"远离了一只却靠近另一只"（旧奖励只看最近单怪的距离桶变化）。
3. **buff 几乎不捡**（0.12/0.16），随机刷新、遇到概率低，纯奖励触发不了。

v4 的全部改动收敛在 `agent_ppo/feature/preprocessor.py` 一个文件，围绕**双怪**这一核心矛盾重写奖励：

- 新增**双怪几何**（距离桶 + 相对方向 → 夹角 spread）与**综合安全度** `dual_safety`；
- 把穿梭奖励从"最近单怪距离桶变化"改写成 **`_calc_flash_landing_reward`**（考核落点对两怪的安全度、是否死角、使用时机）；
- 新增**包夹夹角奖惩** `survive_reward -= 0.1 * spread_delta`；
- 新增 **buff 靠近引导**（相对安全时朝视野内 buff 靠；
- 回退 v2 被证伪的两处冷启动改动，**保留** v2 的 advantage batch 标准化。

#### 6.2.1 双怪几何与综合安全度（v4 核心新增之一）

**设计意图**：官方给每只怪两个"确定字段"——`hero_l2_distance`（英雄↔怪的距离桶，0–5）与 `hero_relative_direction`（英雄视角下的相对方向，1–8）。用它们可以在**不依赖坐标单位**的前提下刻画"两只怪是否正在收拢包夹"。

**(a) 方向 → 弧度**（`_dir_to_angle`，650–666）

```python
mapping = {1:0.0, 2:π/4, 3:π/2, 4:3π/4, 5:π, 6:-3π/4, 7:-π/2, 8:-π/4, 0:0.0}
```

**几何示意**（spread 的物理含义）：

```
   两怪相对英雄的方位角差 ang_diff（取 ≤π 的一侧）

   ① 同向（spread≈0）          ② 垂直（spread≈0.5）        ③ 对面包夹（spread≈1）
        怪B                          怪B                        怪B
         ↑                            ↑                          ↑
         |                            |                          |
   英雄 →→ 怪A                  英雄 ─→ 怪A              英雄   ↑↓（两侧合围）
         （都来自同一侧，            （挡住两个方向，           （一前一后，最危险）
           逃一边就都甩开）            逃一个方向即可）

   spread = ang_diff / π  ∈ [0,1]
```

**(b) 提取可见怪几何**（`_extract_monster_geometry`，668–678）

```python
geo = [(m["hero_l2_distance"], _dir_to_angle(m.get("hero_relative_direction",0)))
       for m in self.monsters]          # 只取视野内 self.monsters（非 all_monsters）
geo.sort(key=lambda g: g[0])            # 按距离桶升序 → geo[0] 最近
```

注意：只用**视野内**怪（`self.monsters`），所以出视野的怪不计入包夹判断——这是 POMDP 下的合理近似，但也意味着"其中一只怪暂时不可见时，dual_safety 会回退到单怪口径"。

**(c) 综合安全度**（`_calc_dual_safety`，680–694）

```python
if not geo:                      return 1.0, 0.0          # 视野无怪 = 绝对安全
near_safety = geo[0][0] / 5.0                             # 最近怪桶 0-5 → 0.0-1.0
spread = 0.0
if len(geo) >= 2:
    ang_diff = abs(geo[0][1] - geo[1][1])
    if ang_diff > π: ang_diff = 2π - ang_diff             # 取 ≤π 一侧
    spread = ang_diff / π                                 # 0 同向 / 1 对面包夹
safety = near_safety * (1.0 - 0.4 * spread)               # 包夹最多额外打 4 折
return safety, spread
```

- **值域**：`dual_safety ∈ [0, 1]`；视野无怪 = 1.0；最近怪贴脸(桶 0) 且被对面包夹 = 0。
- **落点奖励的基准**正是 `dual_safety` 的**帧间增量**（见 6.2.2）。
- 每帧在 `pb2struct` 中保存上一帧值（`896–900`）：

```python
self.last_dual_safety  = self.dual_safety
self.last_monster_spread = self.monster_spread
self.monster_geo = self._extract_monster_geometry()
self.dual_safety, self.monster_spread = self._calc_dual_safety(self.monster_geo)
```

**(d) 复位初值**（`reset`，190–198）：

```python
self.monster_geo = []
self.dual_safety = 1.0;  self.last_dual_safety = 1.0
self.monster_spread = 0.0; self.last_monster_spread = 0.0
self.buff_dist = 999.0; self.last_buff_dist = 999.0
```

> **注意**：`dual_safety`/`spread` **不进入 480D 特征**（特征里只有 `_get_monster_feature_v2` 的 10D×2 与安全热力图等）。它们是**纯奖励侧信号**——即 v4 通过奖励把"双怪几何"注入学习，而非直接喂给网络。这一点是理解 v4 的关键，也是 §10 的风险点之一。
#### 6.2.2 穿梭落点奖励（v4 核心新增之二）

`_calc_flash_landing_reward`（696–723）**替换**了 v2 的 `_calc_flash_reward(action, min_dist, last_min_dist)`。核心思想：穿梭不能再只看"最近单怪的距离桶变化"，而要看**落点相对两怪的综合安全度、落点是否死角、以及是否值得在这个时机用**。

```python
def _calc_flash_landing_reward(self) -> float:
    if not (8 <= self.last_action <= 15):        # 上一帧不是穿梭
        return 0.0
    safety_gain = self.dual_safety - self.last_dual_safety     # 帧间安全度增量
    escape_options, _ = detect_dead_ends(self.map_data[0], self.cur_pos)
    is_dual_phase = self.frame_no >= 300 or self.monster_count >= 2

    if is_dual_phase:
        if safety_gain > 0 and escape_options >= 3:            # 成功且落点开阔
            return min(1.0, 0.4 + 2.0 * safety_gain)
        if escape_options < 3:                                 # 落点死角
            return -0.3
        if safety_gain < 0:                                    # 落点更危险
            return -0.2
        return 0.0
    else:                                                      # 单怪阶段(<300)
        if self.last_min_monster_distance <= 1 and safety_gain > 0:
            return 0.2                                         # 仅近身危急且成功
        return -0.1                                            # 否则默认小罚
```

**逐相位解读**：

| 判断位 | 含义 | 数据来源 |
|---|---|---|
| `8 <= last_action <= 15` | 上一帧是"空间穿梭" | `get_legal_action` 中动作 8–15 |
| `safety_gain` | 落点相对**两怪**的安全度增量 | `dual_safety - last_dual_safety` |
| `escape_options >= 3` | 落点开阔（≥3 个方向可走 3 步） | `feature_utils.detect_dead_ends` |
| `is_dual_phase` | 进入双怪阶段 | `frame_no>=300` **或** `monster_count>=2` |
| `last_min_monster_distance<=1` | 上一帧怪贴脸（桶 0/1） | `pb2struct` 每帧更新 |

**奖励值域**：双怪成功 `+0.4 ~ +1.0`；双怪落死角 `−0.3`；双怪更危险 `−0.2`；单怪成功 `+0.2`；单怪默认 `−0.1`。

**与 v2 的差异（行为层）**：

- v2 只看"最近单怪距离桶"增减（`escaped = min_dist - last_min_dist`），无法识别"远离了一只、靠近另一只"的假逃生；v4 用 `dual_safety` 统一刻画两只怪，规避了这一点。
- v2 对"危险中用了没拉开"给 `−0.1`、对"安全时浪费"给 `−0.05`；v4 把"该不该用"的责任下沉到**相位划分**：单怪阶段几乎一律 `−0.1`（逼模型把技能留到双怪窗口），只有贴脸成功才给 `+0.2`。
- ※ 语义陷阱：单怪阶段的默认 `−0.1` 是"只要这一帧用了穿梭就罚（除贴脸成功外）"。由于 `reward_process` 的判定是 `if self.last_action >= 0`（`1142`），**不含 `and self.monsters`**（v2 有），所以视野无怪时用了穿梭也会吃 `−0.1`。设计上应理解为"单怪期禁止滥用"。

#### 6.2.3 包夹夹角奖惩（v4 核心新增之三）

```python
# reward_process, 1148-1149
spread_delta = self.monster_spread - self.last_monster_spread
survive_reward -= 0.1 * spread_delta
```

- `spread_delta > 0`（夹角张开、包夹收紧）→ **惩罚**；`spread_delta < 0`（夹角收拢、脱离包夹）→ **奖励**。
- 每帧幅度：`|0.1 × Δspread|`，Δspread 单帧最大约 1 → 单帧最多 ±0.1（与 `_calc_survive_reward` 基础量 0.02 同量级，量级合理）。
- 这是 v2"最近单怪距离"**完全感知不到**的信号：两只怪分处两侧时，最近怪距离可能不变，但 `spread` 会升高——v4 用这一项补上了。

> **潜在符号歧义（重要观察点）**：设计文档写"夹角收紧（包夹）惩罚、夹角展开奖励"，但代码里 `spread` 越大=越接近**对面包夹**（越危险）。因此 `spread_delta > 0` 实际是"包夹变得更紧"→ 罚，与文档结论一致；只是文档用词"收紧/展开"与代码变量名的直觉方向相反，读代码时以**代码**为准。详见 §10 风险点。

#### 6.2.4 buff 引导（v4 核心新增之四）

两处：

**(a) 拾取奖励**（1129–1130，继承 v2，未改数值）：`if self.buff_get > 0: survive_reward += 1.0`。注释由 v2 的"后期风筝关键"改成 v4 的"拾取给 +1.0、计入生存通道"。

**(b) 靠近奖励**（1153–1156，v4 新增）：

```python
if self.buff_found and self.min_monster_distance >= 3 and self.last_buff_dist < 900:
    buff_approach = self.last_buff_dist - self.buff_dist
    if buff_approach > 0:
        survive_reward += min(0.04, 0.02 * buff_approach)
```

- 触发条件：**视野内发现 buff** 且 **当前距最近怪 ≥3 桶（相对安全）** 且 **上一帧 buff 距离有效（<900）**。
- 每步奖励：`min(0.04, 0.02×接近格数)`，即靠近越快奖励越高，封顶 0.04/步。
- 距离来源：`pb2struct` 每帧用 `np.hypot` 算欧氏距离（857–864），`buff_found=False` 时置 999。

**设计意图与局限**：给式样稀疏的 buff 一个"往那边走"的密集塑形信号。但 (1) 只在 `min_monster_distance>=3` 时给，双怪压近就停； (2) 亮度 0.04/步 远小于生存/宝箱，实测 buff 只从 0.16→0.22（§2.3），说明**触发频率极低**（buff 随机刷新、遇到概率低）才是根因。这一点与 §10 的"倒因为果"批评一致。

**GAE**（`sample_process` 55–65 → `_calc_reward` 68–79）：

```python
for i in range(len-1): list[i].next_value = list[i+1].value
gae = 0.0
for rl_info in reversed(list):
    delta = -value + reward + γ·next_value
    gae = gae·γ·λ + delta
    advantage = gae
    reward_sum = gae + value
```

- **多通道**：`reward` 是 3 维（step/treasure/survive），GAE 对三维**逐元素**计算（numpy 广播），得到 3 维 advantage / reward_sum。

## 10. 设计评价：优点 / 风险 / 可改进点

### 10.1 优点

1. **诊断纠偏到位**：v4 正确识别"~340 步死亡=双怪包夹"这一真实瓶颈，并用官方确定字段（`hero_l2_distance`/`hero_relative_direction`）构造几何量，不依赖坐标单位，鲁棒。
2. **改动面极小、可归因**：只改 1 个文件 6 处，且保留了唯一被验证正确的 v2 修复（advantage 标准化），符合"每轮只改 1–2 个变量"的迭代纪律。
3. **奖励信号粒度细**：`dual_safety` 差分把"落点是否更安全"这一难以直接观测的量变成可塑形信号；`spread_delta` 补上了单怪距离感知不到的包夹维度。
4. **相位化使用技能**：用 `is_dual_phase` 把"何时用穿梭"编码进奖励结构，比 v2 的逐次奖惩更有结构性。

### 10.2 风险与疑点

1. **几何量不进特征，靠奖励"隔空喊话"**：`dual_safety`/`spread` 只影响奖励、不进入 480D 特征（§6.2.1(d)）。策略网络无法直接"看到"夹角，只能通过奖励的时序关联间接学——**信用分配困难**，可能是"300 步后 spread 仍控制不住"的原因之一。
2. **包夹奖惩符号易误读**：`spread` 大=对面包夹=危险，但设计文档措辞"夹角收紧惩罚/展开奖励"方向相反（§6.2.3）。若后续维护者按文档直觉改符号，会反向。建议代码旁注释明确"spread 大=危险"。
3. **单怪期"用即罚"过于一刀切**：单怪期除贴脸成功外一律 `−0.1`（696–723），且判定不含 `self.monsters`（1142 去掉了 v2 的 `and self.monsters`）。若视野无怪（怪暂时不可见）时用穿梭也吃罚，可能误伤。
4. **buff 靠近触发窗口极窄**：`min_monster_distance≥3` 且 `buff_found` 且上一帧距离有效（1153）。双怪逼近时（桶≤2）完全不触发，而恰恰双怪期最需要加速；实测 buff 仅 0.16→0.22，说明**根因是 buff 遇敌/刷新频率，不是奖励不够**——0.04/步的塑形无法弥补"遇不到"。
5. **方差极大未缓解**：29 步速死 vs 675 步（§2.4）。终局失败罚 `−10·(1−frame_norm)` 在速死时接近 −8.7（§6.7），单帧大额负奖励会显著扰动 value 学习；truncation 未做 V(s_T) bootstrap（§6.5，末帧 `next_value=0`），对"活到 1000 步"的胜利样本价值估计有偏。
6. **`dual_safety` 只用视野内怪**：出视野的怪不计入（668–678 用 `self.monsters`），POMDP 下"看不见就以为安全"，可能在怪刚出视野又折返的瞬间误判。

> 上述 2、3、4、5、6 中，第 5 的"未做 bootstrap""大额失败罚"与第 1 的"不进特征"是可通过读代码**确认**的结构性事实；其对最终指标的具体贡献量（未确认），需消融实验。

### 10.3 可改进点（与 v4 文档 §五 呼应）

1. **把双怪几何写进特征**：给 `dual_safety`/`spread`/两怪夹角直接增维进 480D（或加一路子 MLP），让策略"看得见"，而非仅靠奖励。
2. **单怪期改为条件触发**：单怪期只在 `last_min_monster_distance<=1` 时罚下用技能，其余不罚不奖，避免误伤。
3. **buff 塑形扩窗**：把靠近奖励的 `min_dist>=3` 放宽到 `>=2`，或对"视野内存在 buff"本身给少量占位奖励；更根本的是缩短 `buff_cooldown=200` 以增遭遇率。
4. **PPO 稳定性**：lr 退火、value 归一化、truncation bootstrap、RND 奖励 EMA std 归一化（v4 文档 §五.3）。
5. **课程学习**：先单怪练走位、再双怪练包夹、最后开 500 加速（v4 文档 §五.1）。
6. **POMDP 记忆**：主干接 GRU，怪出视野后保留追踪（v4 文档 §五.4）。
