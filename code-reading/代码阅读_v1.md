## 2. 版本概览

### 2.1 任务目标（一句话）

单英雄"小胖鹅"在 **128×128 栅格地图**中，**1000 步内**躲避 **2 只怪物**追击，并尽可能多地收集宝箱。

关键设定：

- **动作空间 16**：`0–7` 为八方向移动；`8–15` 为八方向"空间穿梭"技能（直线 10 格 / 斜向 8 格，冷却 100 步）。
- **英雄视野 21×21**：局部可观测，本质是 POMDP。
- **第 2 只怪物**默认在第 **300 步**出现（`monster_interval=300`）。
- **怪物加速**默认在第 **500 步**后由 1 格/步变为 2 格/步（`monster_speedup=500`），此后**快于英雄**。
- **计分**：`总分 = 存活步数 × 1.5 + 宝箱数 × 100`。

### 2.2 v1 的一句话改动

> **一句话**：v1 在官方模板基础上，把 `preprocessor.py` 里三处预留的奖励 `TODO` 填写为可运行实现——**空间穿梭技能奖励**、**宝箱收集时机奖励**、**宝箱收集权重 + buff/探索奖励**，并为此补充了两个状态量 `visited_count` / `last_visited_count`。

这是 v1 相对 `_orig_extract` 基线的**全部改动**（详见第 9 节 diff）。工程骨架、模型结构、算法实现、配置项均未改动。

### 2.3 50 局评估指标

| 指标 | 数值 | 解读 |
|---|---|---|
| 总分 | **927.99** | 平均分，对应约 342 步存活 + 4 个宝箱 |
| 终止步数 | **342.66** | 远低于 1000 步上限，说明大量对局早早失败 |
| 宝箱数 | **4.14** | 10 个宝箱中平均只吃到约 4 个 |
| 技能（穿梭）次数 | **3.78** | 1000 步里平均只用 3.78 次，且 CD=100，≈ 几乎不用 |
| buff 次数 | **0.12** | 平均每 8 局才捡 1 次加速 buff，≈ 完全不捡 |

### 2.4 已知问题（来自项目内 `PPO_v2_设计与优化路线.md`，均为可引用事实）

1. **早期收敛后进入平台期**：总分 2–3h 升到 1200–1400 后震荡，不再上升，属局部最优。
2. **通关率 ≈ 0**：抽样 GAMEOVER 全部 `FAIL`，无 `WIN`；好局也活不到终点（卡在 ~340~500 步，死在第二只怪出现后的双怪包夹）。
3. **核心技能未习得**：空间穿梭几乎不用、加速 buff 几乎不捡——而 500 步后怪物速度 2 > 英雄速度 1，不会这两样理论上必死。
4. **策略方差极大**：相邻两局 29~675 步，对开局高度敏感。
5. **工程侧正常**：无错误日志、样本生产消耗比 ~20、CPU/内存平稳——问题在算法而非工程。

**根因链（简要）**：穿梭 CD 长（100 步）、开局不可用 → 随机策略下"使用穿梭→成功逃生"的正样本极稀疏 → v1 给的穿梭成功奖励上限仅 0.5，太弱 → 冷启动死循环，永远学不会。

**职责**：`BaseAgent` 的具体实现，串起"预处理 → 模型推理 → 动作采样 → 训练/存档"四件事，并负责给策略输出加**合法动作掩码**。

| `_legal_soft_max` | 215-227 | 掩码 softmax |

**核心逻辑**

1. `__init__`（`:45-66`）：`torch.manual_seed(0)`（`:46`）保证可复现；优化器 `Adam(lr=Config.INIT_LEARNING_RATE_START=3e-4)`（`:49-51`）；`Algorithm(...)`（`:56`）；`Preprocessor()`（`:57`）；三个分类奖励累计器 `step/treasure/survive_reward_sum`（`:62-64`）用于对局结束日志统计。

2. `_predict_with_model`（`:79-104`）：把 480D 特征堆成 `(1, 480)` 送模型；**注意输出顺序**——`[logits, value, target, predict, monster_pred, safety_pred, action_hint]`（`:90-102`），其中 `value` 是 3 维三头价值，`target/predict` 是 RND 的 256 维向量。

3. `predict`（`:106-138`）：`logits` 经 `_legal_soft_max(logits, legal_action)`（`:121`）得到合法动作概率；`_legal_sample(prob, use_max=False)` 采样出训练用 `action`，`use_max=True` 得贪心 `d_action`（`:122-123`）。两者都写进 `ActData`。

4. `observation_process`（`:178-200`）：唯一的特征入口，`feature_process` 返回 `(feature, legal_action, reward, aux_labels)`，`remain_info` 只保留 `aux_labels` 与 `reward`（`:185-188`）；`sub_action_mask` 填 `[1]*Config.NUMB_HEAD`（`:194-197`，本版本 `NUMB_HEAD=1`）。

5. `_legal_soft_max`（`:215-227`）：`tmp = logits - 1e20*(1-legal_action)` 把非法位压到 -1e20，再数值稳定的 softmax，`+1e-5` 防止除零，并多除一个 `1.00001`。该实现与 `model.process_legal_action`、`algorithm._masked_softmax` 是**三处功能重复**的掩码逻辑（见第 10 节）。

**输入输出**

- 入：`env_obs`（dict）
- 出：`ObsData(feature=480D, legal_action=16D, sub_action_mask=[1])` 与 `remain_info={aux_labels:20D, reward:[3]}`

#### 6.2.2 `pb2struct`：观测解析（`:742-849`）

按部就班地把 `env_obs` 摊平到内部字段，要点：

1. **步数**：`step_no = obs["step_no"]`，`frame_no = step_no`（`:754-757`）；`frame_no_norm = norm_val(frame_no, 3000)`。
2. **位置**：`cur_pos = (hero.pos.x, hero.pos.z)`，`cur_pos_norm = norm_val(cur_pos, 128, -128)`（`:759-760`）。
3. **技能**：`legal_act = obs["legal_action"]`，`skill_usable = any(legal_act[8:16])`（`:766-769`）；`speed_up = hero["buff_remaining_time"] > 0`；`skill_cd = hero["flash_cooldown"]`（`:770-771`）。
4. **地图更新**：用 `map_info` 更新障碍层 `map_data[0]`；用 `visit_view_mask`（11×11 全 1）更新访问层 `map_data[1]`（`:775-782`）。随后 `visited_norm = map_data[1].mean()`，`visited_count = int(map_data[1].sum())`（`:783-786`，后两行 **v1 新增**）。
5. **organ 分类**：`sub_type==2` 为 buff（`buff_found/buff_status/buff_pos`），`sub_type==1 且 status==1` 为宝箱，收集进 `treasure_list`（`:795-804`）。
6. **宝箱特征**：`feature_treasures_pos` = 每个宝箱一个 6D `_get_pos_feature`，补齐到 13 个，按第 6 维（归一化距离）升序排序后取前 13（`:810-815`）——即**最多保留 13 个最近的宝箱**。
7. **收集计数**：`treasure_get = treasures_collected - last_treasure_count`（`:819-820`）；`buff_get = collected_buff - last_buff_count`（`:822-823`）。这两个"本步增量"是奖励函数的关键输入。
8. **怪物分流**：`all_monsters = frame_state["monsters"]`；`monsters = [is_in_view==1]`（仅视野内）；`monster_count = len(all_monsters)`（`:827-830`）。`min_monster_distance = min(hero_l2_distance)`，无可见怪物时设 5（`:832-836`）。
9. **时序与访问更新**：`temporal_state.update(self.monsters, cur_pos, last_action)`（`:844`）；`update_position(hero_grid_pos)`（`:849`）。

#### 6.2.3 特征子模块（每段的语义与维度）

**① 宝箱位置 `feature_treasures_pos` = 6×13 = 78D**（`_get_pos_feature`, `:224-242`）
每个宝箱 6 维：`[found, cos(方向x), cos(方向z), target_x_norm, target_z_norm, dist_norm]`。距离用 `norm_val(dist, 1.41*128)` 归一。这是"注意力"机制里的 Key/Value 主体之一。

**② buff 特征 = 6D + 2D = 8D**（`:806` 与 `:950-955`）
`feature_buff_pos`（6D，同 `_get_pos_feature`）+ `[buff_status, norm_val(buff_cooldown,100)]`（2D）。

**③ 怪物特征 v2 = 10×2 = 20D**（`_get_monster_feature_v2`, `:244-339`）
每只怪物 10 维：`exist(1) + precise_dist(1) + dist_bucket(1) + 方向(2) + 速度(2) + danger(1) + 预测位置(2)`。
- 距离用**桶** `hero_l2_distance`（0–5），经 `bucket_centers=[15,45,75,105,135,165]` 映射回估计距离（`:265-270`）。
- 速度由 `last_monster_positions` 差分得到（`:291-302`）。
- `danger_level = dist_danger*0.7 + approach_factor*0.3`（`:317`），`approach_factor` 用速度与"怪物→英雄"方向的点积量化**是否在逼近**（`:305-315`）。
- 预测位置 = `monster_pos + vel*4*5`，即**未来 5 步线性外推**（`:319-320`）。
- 占位：`monster is None` 返回 `[0,1,1,0.5,...]`；`is_in_view==0` 返回 `[0.5,1,1,...]`（`:257-261`）。用 `all_monsters` 保证**槽位对齐**（`:917-922`）。

**④ 进度特征 = 12D**（`_get_progress_feature`, `:341-395`）
`[剩余步数比, 已用步数比, 第二只怪倒计时, 加速倒计时, 穿梭可用, 怪物数/2, 宝箱进度, 剩余宝箱比, buff可用, buff生效, 后半局标志, 危险阶段标志]`。其中 `monster_speed_boost_step=500` 硬编码（`:347`）。

**⑤ 时序特征 = 24D**（`_get_temporal_feature`, `:397-434`）
每只怪物：历史 5 帧相对位置 = 5×2 = 10D，加"速度变化趋势"2D → 12D/怪 ×2 = 24D。历史轨迹取自 `TemporalState.monster_history`，`velocity_trend` 用最近速度与历史均速之差（`:92-110`），用于捕捉怪物**加减速/变向**。

**⑥ 路径规划特征 = 16D**（`_get_path_planning_feature`, `:436-470`）
8 方向逃生评分（`calc_escape_routes`）+ 死角逃生方向数（`detect_dead_ends`）+ 最近安全区接近度（`find_nearest_safe_zone`）+ 5 个最近宝箱路径是否安全（`check_treasure_safe_path`）+ 拥挤度 = 8+1+1+5+1 = 16D。

**⑦ 宝箱优先级 = 8D**（`_get_treasure_priority_feature`, `:472-526`）
Top3 优先级分数（3D）+ Top3 安全时间窗（3D）+ 最优宝箱方向（2D）= 8D。

**⑧ 安全热力图 = 16D**（`_get_safety_heatmap_feature`, `:528-535`）
把地图切成 4×4 网格，每格取"到最近怪物的距离/60"作为安全分，`flatten` 成 16D。

**⑨ 辅助任务标签 = 20D**（`_get_aux_labels`, `:612-620`）
= 怪物预测标签 8D（`:539-583`）+ 安全分类标签 4D（`:585-601`，4 象限安全均值）+ 动作建议标签 8D（`:603-610`，即当前 8 方向逃生评分）。用于第 6.6 节的辅助损失。

```python
gae = 0.0
for rl_info in reversed(list_sample_data):
    delta = -rl_info.value + rl_info.reward + gamma * rl_info.next_value
    gae = gae * gamma * lamda + delta
    rl_info.advantage = gae
    rl_info.reward_sum = gae + rl_info.value
```

由于 `value/reward/next_value` 都是 **3 维**，上述运算是**逐通道**的（step/treasure/survive 各自一套 GAE）。`gamma=0.99, lamda=0.95`（`conf.py:55-56`）。注意末尾样本的 `next_value` 未被显式置零（最后一帧保留 `next_value=0` 初值，实际即截断），是 v1 的一个偏置点（见第 10 节）。

**`learn`（`:47-125`）流程**：把样本里的 `obs/legal_action/act/prob/reward/reward_sum/advantage/value/next_value/aux_labels` 堆成 batch（`:52-61`）→ `set_train_mode` + 清梯度（`:65-66`）→ 前向（`:70`）→ `_compute_loss`（`:75-86`）→ `backward`（`:91`）→ `clip_grad_norm_(0.5)`（`:95-96`）→ `optimizer.step()`（`:98`）。每 60 秒把 `value_loss/policy_loss/entropy_loss/rnd_loss/aux_loss/reward` 上报监控（`:110-125`）。

**`_compute_loss` 三块损失**：

1. **Value 损失（`:144-158`）**：`tdret = reward_sum`（GAE return）；对 `value_clip = old_value + clamp(value_pred-old_value, ±clip)` 与 `value_pred` 取 `0.5*max(square(tdret-value_clip), square(tdret-value_pred)).mean()`。**注意** `value` 与 `tdret` 都是 3 维，未做 squeeze 时按元素算，等价于三头各自回归。
2. **Policy 损失（`:160-180`）**：`prob_dist = _masked_softmax(label_out, legal_action)`；`entropy = -Σ p·log p`；`ratio = new_prob/old_action_prob`；PPO clip 后 `policy_loss = max(-ratio·A, -clamp(ratio,1±0.2)·A).mean()`。**advantage 未标准化**（三头 GAE 直接平均，`:173-176`），是 v1 方差大的重要原因（v2 会加 batch 内标准化）。
3. **RND 损失（`:182-184`）**：`mean((target-predict)^2)`。
4. **辅助损失（`:186-201`）**：`monster` 用 MSE、`safety` 用 BCE、`action_hint` 用 MSE，权重各 0.1。

**总损失（`:203`）**：`total = vf_coef*value_loss + policy_loss - var_beta*entropy_loss + rnd_loss + aux_loss`。

> 说明：`advantage.reward_mean`、`std` 等被塞进 `info_list` 用于日志，但**未用于标准化**。

### 8.3 子函数分档

**`_calc_survive_reward`（`:677-699`）**：基准 `0.02`，按距离桶调节：

| min_dist | 处理 |
|---|---|
| 0（贴脸） | `×0.5` = 0.01 |
| 1 | `×0.75` = 0.015 |
| 2 | 不变 = 0.02 |
| ≥3 | `+0.01×(min_dist-2)` |

再加距离变化项：拉大距离 `+0.02×Δ`；拉近且 `min_dist≤2` 时 `+0.01×Δ`（Δ 为负）。

**`_calc_flash_reward`（`:639-675`，v1 新实现）**：仅对动作 ∈[8,15] 生效；`escaped = min_dist - last_min_dist`：

| escaped | 条件 | 返回值 |
|---|---|---|
| >0 | 成功拉开 | `min(0.5, 0.15+0.08×escaped)` |
| <0 | 更近（撞墙/方向错） | `-0.08` |
| =0 | 危险中(`last≤2`)保持距离 | `+0.03` |
| =0 | 安全中(`min≥4`)浪费技能 | `-0.05` |
| =0 | 其他 | `0.0` |

**`_calc_treasure_timing_reward`（`:701-727`，v1 新实现）**：本步有收集时，按 `min_dist` 分档：`≥4→1.0`、`3→0.6`、`2→0.2`、`1→-0.4`、`0→-0.8`（鼓励"在安全时收集"）。

| 4 | 访问计数更新 | 状态更新 | 是（基础设施） |
| 5 | 宝箱权重 0→2.5 | 奖励标定 | **是**（宝箱数 0→4.14） |
| 6 | buff/探索奖励 | 奖励新增 | **否/弱**（通道错、力度小 → buff 仍不捡） |

## 10. 设计评价

### 10.1 优点

1. **特征工程扎实、维度自洽**：480D 特征覆盖宝箱/buff/怪物/进度/时序/路径规划/安全热力图/访问图，且 `conf.py:FEATURES`、`model.py:split`、`preprocessor.py` 拼接顺序三处严格对应，可维护性好。
2. **辅助任务设计合理**：怪物预测、安全分类、动作建议三个辅助头（`model.py:106-151`），为策略网络提供了额外的表征学习信号，对 POMDP 尤其有价值。
3. **注意力机制选型得当**：用 Query（全局感知特征）对 Key/Value（宝箱/buff/怪物/时序 token）做注意力（`model.py:267-280`），天然适配"怪物/宝箱数量可变"的场景——槽位对齐（`all_monsters`）配合掩码占位，鲁棒。
4. **最有效改动精准**：改动 5（宝箱权重 2.5）直接让得分从"只有生存分"回到"生存+宝箱"双轮驱动，是 v1 能到 927.99 分的直接原因。
5. **工程健壮性**：容灾检查（`train_workflow.py:94,136`）、定期存档、监控上报、三处掩码 softmax 的数值稳定处理（`_lsm_const_w=1e20`）都体现了官方模板的成熟度。

### 10.2 风险 / 问题

1. **穿梭/buff 冷启动死循环（最致命）**：穿梭成功奖励上限 0.5，而 CD=100、开局不可用；buff 奖励仅 0.5 且归入宝箱通道。正样本极稀疏 → 永远学不会 → 500 步后怪物速度 2>英雄速度 1，**理论上必死**，通关率 0。
2. **advantage 未标准化**：`algorithm.py:173-180` 直接用三头 GAE 平均作为 policy advantage，三通道尺度不统一，导致更新方向抖动、策略方差极大（29~675 步）。
3. **三处重复的掩码 softmax**：`agent._legal_soft_max`、`model.process_legal_action`、`algorithm._masked_softmax` 逻辑同构但各自实现，易不一致。
4. **截断 bootstrap 缺失**：`definition.py:_calc_reward` 末尾样本 `next_value=0`，1000 步截断时未用 `V(s_T)` bootstrap，value 存在偏置（仅靠 +20 终局补偿）。
5. **`phase_weights["explore"]` 定义未用**：探索奖励与相位权重脱节，配置形同虚设。
6. **未观测区域乐观假设**：`reset` 把 `map_data[0]` 初始化为全可通行（`preprocessor.py:154`），规划类特征（逃生/安全区）可能基于错误地图。
7. **POMDP 记忆缺失**：怪物出视野后，特征只保留"最后速度外推 5 步"（`preprocessor.py:319-320`），无法长期预判；缺 GRU/LSTM。
8. **单 epoch 数据复用低**：样本生产消耗比 ~20，replay buffer 巨大但 PPO 只做 1 次更新（配合 `configure_app.toml` 的批量设置），数据效率低。

### 10.3 可改进点（对应后续版本方向）

| 优先级 | 改进 | 依据 |
|---|---|---|
| 高 | 提高穿梭成功奖励上限、加重失败惩罚、新增"危险时不用技能"的机会成本 | 打破冷启动 |
| 高 | policy 前对 advantage 做 batch 内标准化 | 降方差、稳更新 |
| 高 | buff 奖励从 treasure 通道移到 survive 通道并加大 | 修通道+提力度 |
| 中 | 学习率/熵系数退火；课程学习缩短 CD | 突破 500 步天花板 |
| 中 | 截断处 `V(s_T)` bootstrap；value 归一化 | 修 value 偏置 |
| 低 | 合并三处掩码 softmax；清理未用字段 | 代码质量 |
